### 1. FullCalendar（github.com/fullcalendar/fullcalendar）
- **技术栈**：TypeScript，pnpm monorepo + Turbo 构建；官方 React / Angular / Vue 2/3 连接器；插件化按需加载（core + dayGrid / timeGrid / list / interaction / rrule / adaptive 等）。
- **功能完整度**：月/周/日/列表视图，拖拽与边缘调整大小（`interaction` 插件，免费），重复事件通过官方 `rrule` 插件（接 rrule.js）支持，全天/多日事件，now indicator，自定义渲染插槽（`eventContent` 等）极其丰富。**Resource Timeline / Resource Time Grid 为 Premium 付费插件**。
- **可借鉴**：插件化架构（核心 + 可选功能包）；`EventSource` 抽象（events 可以是数组/URL/函数/Feed）；大量渲染插槽与 CSS 变量主题；DateEnv 的时区处理设计。Nextcloud Calendar 也基于它。
- **许可**：核心 MIT 可直接商用；Premium 插件不可白嫖，只能参考交互设计。

### 2. Schedule-X（github.com/schedule-x/schedule-x）
- **技术栈**：TypeScript，Rollup + Vite，Lerna/Nx monorepo；支持 React / Vue / Angular / Svelte / Preact，框架组件可注入替换。
- **功能完整度**：Material Design 风格，暗色模式、i18n、响应式；免费插件：Event Modal、Timezone Select、ICalendar 导入、Event Recurrence、Current Time Indicator、Calendar Controls；**Premium 付费插件：Drag and Drop、Resize、Drag to create、Interactive Event Modal、Sidebar、Scheduling Assistant**。官方给出"自研拖拽创建约 40h、资源视图约 100h"的成本估算作为卖点。
- **可借鉴**：现代 CSS（custom properties）主题定制、Temporal API 时间处理、组件注入式扩展模型；其定价结构本身就是功能优先级参考。
- **许可**：核心 MIT；拖拽/调整大小等关键交互在 Premium 中，商用需付费（一次性买断制）。

### 3. Toast UI Calendar（github.com/nhn/tui.calendar）
- **技术栈**：Preact + Immer + DOMPurify，提供 React/Vue 包装。
- 月（2/3/6 周）/周/日视图、拖拽创建与调整、里程碑/任务日程类型、自定义主题。
- **关键情报：仓库已于 2026 年 9 月归档，停止维护**——新项目不建议选用，但其"里程碑/任务/普通日程三态混合"的设计值得借鉴。MIT。

### 4. React Big Calendar（github.com/jquense/react-big-calendar）
- React 专用，flexbox 布局；月/周/日/agenda 视图；拖拽/resize 通过 addon；本地化需绑定日期库 peer dependency（moment / date-fns / dayjs / globalize）；**重复事件不内置**。
- **可借鉴**：`dayLayoutAlgorithm` 可插拔的重叠布局算法接口；`localizer` 抽象把日期库做成可替换适配器。MIT，全部免费。

### 5. vue-cal（github.com/antoniandre/vue-cal）
- Vue 3（v5 预发布）+ Vite + pnpm；**零第三方依赖**，体积小。years/year/month/week/day 视图 + timeline；拖拽、resize 内置；v5 内置重复事件、split days（按人/资源分栏）、重叠事件布局、约 30 种语言。MIT。注意 v5 稳定版尚未发布。

### 6. Bryntum Calendar（商业，仅参考）
- 功能天花板：day/week/month/year/agenda + **Timeline + Resource 视图**（事件可在资源间拖拽改派）、极高渲染性能。可借鉴资源调度交互与性能优化思路；不可复用其代码。

## 二、完整开源日历产品

### 1. cal.com / cal.diy（github.com/calcom/cal.com）
- **Stars**：~48.6k；**许可**：社区版 MIT。2026 年 4 月 Cal.com 将生产代码转私有，开源社区版独立为 **cal.diy**。
- **技术栈**：Next.js + TypeScript + tRPC + Prisma + PostgreSQL + Tailwind + Turborepo + Zod + NextAuth；测试 Playwright。
- **功能**：预约调度、Google/Microsoft 365/Zoho 日历双向同步、视频会议集成、Stripe 支付、REST API + Webhooks、Web Push、i18n。
- **可借鉴**：**日历提供商抽象层**（Google/Outlook 统一接口）、可用性/忙闲计算引擎、booking 确认流、时区协商展示。它是 booking 而非个人日程，别照搬产品形态。

### 2. Nextcloud Calendar（github.com/nextcloud/calendar）
- **Stars**：~1.2k；**许可**：AGPL-3.0。
- **技术栈**：Vue 前端 + PHP 后端；**渲染基于 FullCalendar，iCal 解析基于 Mozilla ical.js，CalDAV 用自研 c-dav 库**。
- **功能**：多日历、WebCal 订阅、参会人邀请与 free/busy 忙闲查询、提醒（浏览器通知 + 邮件）、显示 Tasks/Deck 卡片 deadline、事件附件、预约 booking。
- **可借鉴**：**最标准的"iCal 为数据源 + FullCalendar 为渲染层 + CalDAV 为同步协议"三层架构**，是做 iCal 互操作的最佳参考实现。AGPL 传染性强，借鉴思路可以，直接抄代码需同样开源。

### 3. Etar Calendar（Android）
- **Stars**：~2.6k；**许可**：GPL-3.0（基于 AOSP Calendar）。
- Kotlin/Java；数据存于 Android 系统 Calendar Provider，自身无同步，靠 DAVx5 等同步。
- 月/周/日/agenda 视图、Material Design 深浅主题、离线本地日历、ICS 导入导出、Agenda 小部件。
- 可借鉴：agenda 小部件形态。

### 4. Tuta Calendar（github.com/tutao/tutanota 内模块）
- GPL-3.0。TypeScript + Rust（tuta-sdk），Mithril 框架，多端原生壳；已拆出独立日历 App。
- **端到端加密日历**（含提醒内容加密）。可借鉴：加密日历的实现路径。

### 5. 自建同步生态（CalDAV 服务器）
Baïkal（PHP）、Radicale（Python，极轻量）、Xandikos（Git 存储）、SOGo（Outlook/ActiveSync 兼容）——若产品要支持标准协议同步，客户端兼容性测试就对着这几个服务器做。

## 三、桌面/本地优先应用

### 1. Super Productivity ★ 重点参考
- **Stars**：~22.2k；**许可**：MIT。
- **技术栈**：Angular + TypeScript + Electron（桌面）+ Capacitor（Android/iOS）+ PWA；本地优先，无需注册。
- **数据/同步**：本地存储 + 多同步后端可选：**SuperSync（端到端加密、可自托管）、Dropbox、WebDAV**。
- **功能**：任务（子任务/项目/标签/看板/艾森豪威尔矩阵）、Planner 时间轴日程、时间追踪与 timesheet 导出、Timeboxing、番茄钟 + Flowtime、休息提醒/抗拖延、CalDAV 集成、Jira/GitHub/GitLab/Trello/Linear 等集成、插件与自定义主题。
- **可借鉴**：**"本地优先 + 可插拔同步后端"的架构决策**；把日程、任务、时间追踪、专注融为一体的产品形态；MIT 许可可深入学代码。

### 2. AppFlowy / AFFiNE / Logseq
- **AppFlowy**（~60k+ stars，AGPL）：Rust + Flutter，Notion 替代品；数据库视图含**日历视图**（数据表按日期字段渲染到月历）；local-first。
- **AFFiNE**：TS/Web 技术栈，docs + 白板 + database，含日历视图。
- **Logseq**（~30k+ stars）：ClojureScript + Markdown/Org 文件本地存储；核心范式是每日 Journal 页面，没有真正的日历视图——但"日记 + 时间戳 + 日程块内联"的用法对"日志型日程"有启发。
- 可借鉴：AppFlowy 证明"数据库日历视图"（任意实体有日期字段即可上日历）比"纯事件日历"扩展性更强；Logseq 的 journal-first 适合作为日程备注层。

## 五、技术路线建议

### 自研 vs 基于开源库

| 方案 | 优点 | 风险 | 结论 |
|---|---|---|---|
| 纯自研渲染 | 完全可控、差异化 UI | 重叠布局/拖拽/时区/性能至少 200+ 工时，重复事件再 +100h | 除非日历是核心卖点，否则不推荐 |
| 基于 FullCalendar | 最成熟、Nextcloud 背书、MIT | 样式定制成本高，资源视图要付费 | **推荐（快速上线）** |
| 基于 Schedule-X | 现代 UI、易定制、多框架 | 拖拽/resize 是 Premium | 推荐（接受付费时） |
| 自研视图 + 借开源算法/模型 | 平衡 | 需要团队有能力 | **长期推荐** |

**推荐组合（分阶段）**：
1. **前端框架**：React 或 Vue 3 + TypeScript + Vite + Tailwind。
2. **日历渲染**：快速版用 FullCalendar 核心（MIT）+ rrule 插件；自研版只参考 FullCalendar/Schedule-X 的分层（grid 渲染层 / 交互层 / 数据层分离），布局算法用标准重叠分列算法，交互（拖拽/resize）用 Pointer Events 自研。
3. **数据层/重复规则**：**rrule.js**（RRULE 解析/展开）+ **ical.js**（iCal 导入导出），数据模型对齐 RFC 5545，天然获得与 Google/Apple/滴答清单互操作能力。
4. **本地存储**：Web 用 **IndexedDB + Dexie.js**（或 RxDB）；桌面（Electron/Tauri）用 **SQLite**。关键是抽象出 Repository 层，双实现。
5. **同步方案**：单用户多设备起步用「变更日志 + last-write-wins + 软删除墓碑」即可；将来做协作再上 CRDT（Yjs/Automerge）或 CalDAV 兼容（对照 Radicale/Baïkal 测试）。
6. **桌面壳**：**Tauri**（Rust，体积小）或 Electron（生态全，Super Productivity 先例）。

## 六、数据模型参考（事件/重复/提醒）

**经典建模 = RFC 5545 (iCalendar) 的关系化版本**：

```sql
Calendar (id, name, color, timezone, is_visible, source: local|ical-sub|caldav)
Event (id, calendar_id, uid,                  -- UID 用于 iCal/CalDAV 互操作
      title, description, location,
      is_all_day, start_at, end_at,           -- 存 UTC + 原时区
      timezone, status: confirmed|tentative|cancelled,
      created_at, updated_at, deleted_at)     -- 墓碑软删除，同步必需
Recurrence (event_id, rrule TEXT,             -- 'FREQ=WEEKLY;BYDAY=MO,WE;COUNT=10'
            exdates: [timestamp],             -- 删除的单次实例（EXDATE）
            rdates: [timestamp])              -- 追加的单次实例（RDATE）
EventOverride (event_id, recurrence_id,       -- "只改这一次"：以原实例起点为主键
               start_at, end_at, title, ...)  -- 覆盖字段（RECURRENCE-ID 语义）
Reminder (id, event_id, offset_minutes,       -- 绝对时间或相对偏移（-10m/-1d）
          channel: in_app|push|email|sound, is_relative)
Attendee (event_id, email, name, role, rsvp_status)
```

**要点**：
1. **不物化重复实例**——只存规则，渲染时用 rrule.js 在视口区间内展开，性能与存储都最优。
2. **单次修改用 Override 表**：改/删某一次，记 `recurrence_id` + 覆盖字段或删除标记；"此事件及后续所有"则拆成两条规则。
3. **提醒多对多**：一个事件多个提醒，相对偏移在重复事件上自动跟随每个实例。
4. 全天事件按"日期"存储且不随时区换算；时间事件存 UTC + 原时区双字段。
5. 同步三要素：**updated_at（LWW）、墓碑、UID 幂等**。
6. 重叠布局算法（渲染层核心，Google Calendar 式）：按开始时间排序 → 传递性重叠聚类 → 簇内贪心分列（列数 = 最大同时重叠数）→ 宽度 = 容器/同组列数并向空邻列扩展。React Big Calendar 的 `dayLayoutAlgorithm` 接口证明该算法做成可插拔是最佳实践。

## 七、值得直接借鉴的功能清单（按优先级）
